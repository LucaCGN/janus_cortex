## Objective

Janus needs one reliable, machine-readable truth surface for every live event and postgame review. The controller, internal LLM, automations, and operator should be able to answer these questions from JSON logs or endpoints without manual artifact archaeology:

- Which event is in scope, and is the worker scope/config safe?
- What is the current score, clock, period, and feed-resolution state?
- What is the current CLOB/account truth for this event?
- What StrategyPlan sleeves exist, which are active, blocked, shadow-only, or eligible?
- What did Janus want to do, what did it actually do, and why?
- Which blockers fired, what scope did they affect, and what would have happened without them?
- Which LLM/PBP/quarter-review traces existed, what model tier handled them, and what decision resulted?
- What budget is available before and after realized-profit add-ons?
- What post-call reconciliation proves execution was safe?

All work below preserves the execution boundary: no order, cancel, submit, sign, broadcast, redeem, worker start, or live-money action outside Janus StrategyPlan/live-worker/order-management gates.

## Observability Contract

Every issue above must either add to `janus_live_event_state_v1` or prove why the data belongs in a narrower artifact. A task cannot close only because code behavior changed; it must also provide a durable JSON/log/endpoint readback.

Minimum common fields:

- `schema_version`
- `event_id`
- `generated_at_utc`
- `source`
- `source_confidence`
- `freshness_status`
- `blockers[]`
- `artifact_paths[]`
- `execution_authority`
- `live_money_authority`

For safety-critical sections, include both the raw evidence and the interpreted decision. Example: direct CLOB trades must show raw observed rows, trust classification, and account-PnL eligibility.
